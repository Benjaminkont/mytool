### 需求
遇到需要日志分析的场景，往往伴随着一下几个特点  
1. 报错很多（一般重复的报错多），如果直接塞到上下文里，会浪费大量 token，所以此时
    1. 统计报错
    2. 最后构建成一个简略的总结
    3. 然后在塞到上下文里
    4. 这个时候就是看能否解决了，然后还解决不了，那就只能全部塞到上下文里
  2. 报错不多，那还说啥呢，直接塞进去就行

有几个可能的方向
1. 计算 token

### 思路

```
log/
├── reader.py       # 读取文件和 STDIN
├── parser.py       # 解析时间、级别、多行异常
├── clustering.py   # 日志模板归类
├── analyzer.py     # 本地统计和关键证据筛选
└── serializer.py   # 根据 Token 预算生成摘要
```
